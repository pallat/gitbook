# วิธีคิดแบบคนเขียนโค้ด

ผมเชื่อว่าหลายๆคนที่ไม่เคยเขียนโปรแกรมมาก่อน เวลาได้พูดคุยกับคนที่เป็นโปรแกรมเมอร์ หรือทำงานในสายงานที่ต้องเขียนโปรแกรมคอมพิวเตอร์ อาจจะประสบกับปัญหาการฟังไม่รู้เรื่อง ไม่เข้าใจว่าเขาพูดอะไร เพราะมันจะมีคำศัพท์แปลกๆ วิธีเรียบเรียงคำพูดแบบแปลกๆ ที่ทำให้การฟังภาษาไทย กลายเป็นเรื่องยากที่จะทำความเข้าใจขึ้นมาทันที

ก่อนอื่นเรามาทำความเข้าใจกันก่อนว่า วิธีการคิดในหัวของพวกโปรแกรมเมอร์นี้เป็นอย่างไร ผมจะยกตัวอย่างเครื่องชงกาแฟอัตโนมัติ ถ้าใครเคยใช้เครื่องชงกาแฟแบบนี้ มันจะมีหน้าจอให้เลือกเมนู เช่น coffee, espresso, cappuchino, latte เป็นต้น พอเรากดเลือกเมนู สักพักเราก็จะได้กาแฟที่ต้องการ นี่คือสิ่งที่เราเห็น

ถ้าให้คนทั่วไปคิดถึงขั้นตอนที่เกิดขึ้นกับเครื่องชงกาแฟอัตโนมัติ อาจจะได้ขั้นตอนประมาณนี้

1. เอาแก้วไปวางในแท่น
2. เลือกเมนูที่อยากได้
3. รอจนได้กาแฟ

ส่วนสิ่งขั้นตอนที่โปรแกรมเมอร์เห็นคือ

1. แสดงเมนู
   1. เมนูที่ 1 coffee
   2. เมนูที่ 2 espresso
   3. เมนูที่ 3 cappuchino
   4. เมนูที่ 4 latte
2. ถ้า user (หมายถึงคนที่ต้องการกาแฟ) มากดปุ่ม coffee
   1. เปลี่ยนหน้าจอให้แสดงการชง
   2. ถ้ามีค่าพารามิเตอร์[^1]ให้ทำ pre-brewing จะต้องปล่อยน้ำร้อนออกมา 10ml
   3. บดกาแฟตามจำนวนพารามิเตอร์ โดยมีค่าเริ่มต้นที่ 15กรัม
   4. อัดผงกาแฟลงในถ้วยสกัดกาแฟ
   5. ต้มน้ำให้เดือดอุณหภูมิตามค่าพารามิเตอร์ โดยมีค่าเริ่มต้นที่ 95องศาเซลเซียส
   6. อัดน้ำร้อนเข้าไปในถ้วยสกัดกาแฟตามค่าพารามิเตอร์ โดยมีค่าเริ่มต้นที่ 200ML
   7. นำกากกาแฟไปทิ้ง
   8. เปลี่ยนหน้าจอให้กลับไปแสดงเมนู

นี่เป็นขั้นตอนคร่าวๆ ที่โปรแกรมเมอร์คิด ซึ่งความจริงอาจจะต้องละเอียดยิ่งกว่านี้ โดยถ้าจะแบ่งแยกว่าการคิดในแบบ user เราอาจจะเรียกสิ่งนั้นว่า Journey หรือเรียกว่า User Experience ก็ได้เหมือนกัน ส่วน workflow ของเครื่องจริงๆ เบื้องหลังจะมีการเขียนโปรแกรมมาควบคุมตามขั้นตอนแบบที่โปรแกรมเมอร์คิด

สิ่งที่โปรแกรมเมอร์คิด มักจะต้องสัมพันธ์กับเวลาในแต่ละเสี้ยววินาที ว่าจะต้องเกิดเหตุการณ์อะไรบ้าง ที่มันจะไม่สามารถเกิดขึ้นได้เอง ถ้าเราไม่สั่งให้มันเกิดขึ้น

[^1]: ค่าพารามิเตอร์ คือค่าตัวแปร คล้ายๆกับตัวแปรในการคำนวณแบบคณิตศาสตร์
